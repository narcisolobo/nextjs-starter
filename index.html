Presenting complaint

Sep 28

I was starting a side project called So What? The first thing create-next-app gave me was this:

[WARN] deprecated eslint@9.39.5. 10.11.0 is not
deprecated, outside the range you declared.

ESLint 9 had reached end of support, so every new Next.js app started life with a deprecation warning.

First opinion

Sep 28

Ignore it. eslint-config-next pulls in eslint-plugin-react and eslint-plugin-import, and neither supports ESLint 10. Nothing is broken, so stay on 9.

That was good advice, and I didn't take it. I have LAG syndrome: if there's a latest and greatest, I want it.

Treatment

Sep 29

The next afternoon I dropped eslint-config-next and rebuilt its rule set from plugins that do support ESLint 10:

  • @eslint-react/eslint-plugin instead of eslint-plugin-react
  • eslint-plugin-import-x instead of eslint-plugin-import
  • eslint-plugin-jsx-a11y-x instead of eslint-plugin-jsx-a11y

@next/eslint-plugin-next works fine on its own. No peer warnings. Then I wondered whether this could just be my create-next-app, and it can: --example takes any GitHub repo.

Complication

Sep 29

Before making the template, I ran pnpm up --latest. It moved TypeScript from 5.9.3 to 7.0.2 with nothing more than a peer warning. Lint stopped working:

Cannot read properties of undefined (reading 'Intrinsic')

TypeScript 7 doesn't ship the JavaScript API that typescript-eslint needs. The sensible fix was to go back to TypeScript 5. See diagnosis. Instead I followed the TypeScript team's notes on running 7 alongside 6: tsc is TypeScript 7, and ESLint and next build get TypeScript 6 under the typescript name.

The template went up on GitHub that afternoon.

Relapse

Oct 10

Eleven days later, someone on r/nextjs posted the same deprecation warning plus 5 high severity vulnerabilities, and asked if it was just them. Before replying, I audited my own template. It was pinned to next 16.3.6, which had a high-severity SSRF in image optimization by then.

A template is only as current as the last time someone remembered to update it. I hadn't.

Current regimen

Ongoing

Remembering isn't a plan, so now it updates itself.

  • Renovate opens one PR a week for minor and patch updates. It merges once CI passes: peer check, lint, typecheck and build.
  • Security fixes don't wait for the weekly batch.
  • Major versions wait for me, because a major release is what broke lint the first time.

Not a complication

Oct 10

Those 5 highs from the Reddit post are one advisory in braces, counted once for every package in the chain under @next/eslint-plugin-next. My template has it too. The maintainer disputes the advisory, and I traced the code: the plugin only globs settings.next.rootDir from your own ESLint config. The template doesn't set it, so the vulnerable code never runs.

Don't npm audit fix --force it. That downgrades you to eslint-config-next 14.

Contraindications

If you don't have LAG syndrome, plain create-next-app is the better choice. It's the official default, and the warning is harmless.

If you want the update automation but not the new majors, the README shows how to drop TypeScript 7 or go back to eslint-config-next.

Prescription

pnpm create next-app --example "https://github.com/narcisolobo/nextjs-starter" my-app

App Router, src/, Tailwind CSS 4 and React Compiler come with it. Setup steps, scripts and the full ESLint mapping are in the README.
